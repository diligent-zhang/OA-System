# OA 办公管理系统 — 接口说明文档

> Base URL：`http://localhost:8080`　前端：`http://localhost:5173`
> 所有业务接口需携带请求头：`Authorization: Bearer <token>`（登录/注册接口除外）
> Token 临近过期（剩余 < 30 分钟）时，响应头 `X-Renew-Token` 自动下发续期 Token，前端无感替换。

## 统一返回格式

```json
{ "code": 200, "message": "操作成功", "data": {} }
```

| code | 含义 |
|---|---|
| 200 | 成功 |
| 400 | 参数/业务校验失败 |
| 401 | 未登录或 Token 失效（前端自动跳转登录页） |
| 403 | 权限不足（员工访问管理员接口） |
| 404 | 资源不存在 |
| 500 | 服务器内部错误 |

分页数据统一为 `PageResult`：`{ total, pageNum, pageSize, list }`。

## 1. 认证模块 `/api/auth`

### 1.1 登录 `POST /api/auth/login`（公开）

```json
// 请求
{ "username": "admin", "password": "123456" }
// 响应
{ "code": 200, "message": "登录成功", "data": {
    "token": "eyJhbGciOiJIUzM4NCJ9...",
    "userId": 1, "username": "admin", "role": "ADMIN", "empId": 9, "name": "系统管理员" } }
```
失败：`用户名或密码错误`(400)；禁用账号：`账号已被禁用，请联系管理员`(403)。

### 1.2 注册 `POST /api/auth/register`（公开）

请求字段：`username, password, name, gender(0/1), phone, email, deptId(选填,须为二级部门), hireDate(选填)`
成功后同步创建员工档案（工号自动生成为 `EMP+年份+4位序号`）与 `EMPLOYEE` 角色账号。

### 1.3 用户名唯一性校验 `GET /api/auth/username-exists?username=xxx`（公开）

响应 `data: true/false`。

### 1.4 退出 `POST /api/auth/logout`（需登录）

## 2. 员工管理 `/api/admin/employees`（ADMIN）

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/admin/employees` | GET | 分页查询，参数：`name`（模糊）、`empNo`（模糊）、`deptId`、`status`、`pageNum`、`pageSize` |
| `/api/admin/employees/{id}` | GET | 详情 |
| `/api/admin/employees` | POST | 新增（同步建账号，初始密码 `123456`），必带 `username` |
| `/api/admin/employees/{id}` | PUT | 编辑 |
| `/api/admin/employees/{id}` | DELETE | 删除（级联删除登录账号） |
| `/api/admin/employees/batch` | DELETE | 批量删除，请求体 `[1,2,3]` |
| `/api/admin/employees/{id}/password/reset` | PUT | 重置密码为 `123456` |
| `/api/admin/employees/{id}/status?status=0\|1` | PUT | 禁用/启用登录账号 |

列表行示例（`EmployeeVO`）：

```json
{ "empId": 9, "empNo": "EMP20260000", "name": "系统管理员", "gender": 1,
  "phone": "13800000000", "email": "admin@tianyu.com", "deptId": 5,
  "deptName": "行政部", "hireDate": "2026-01-01", "status": 1,
  "username": "admin", "accountStatus": 1 }
```

## 3. 部门管理

| 接口 | 方法 | 权限 | 说明 |
|---|---|---|---|
| `/api/admin/depts?keyword=&pageNum=&pageSize=` | GET | ADMIN | 分页 + 名称关键词，含 `parentName`、`empCount` |
| `/api/depts/tree` | GET | 登录 | 两级树（`children` 数组），两端下拉共用 |
| `/api/admin/depts` | POST | ADMIN | 新增 `{deptName, parentId, sortNo}`，最多两级 |
| `/api/admin/depts/{id}` | PUT | ADMIN | 编辑 |
| `/api/admin/depts/{id}` | DELETE | ADMIN | 删除；有在职员工或子部门时返回 400 并说明原因 |

## 4. 公告管理

| 接口 | 方法 | 权限 | 说明 |
|---|---|---|---|
| `/api/admin/notices` | GET | ADMIN | 分页，参数 `title`(模糊)、`type`(1通知/2公告/3制度)、`beginTime`、`endTime` |

| `/api/admin/notices/{id}` | PUT | ADMIN | 编辑（不改变上下架状态） |
| `/api/admin/notices/{id}/toggle` | PUT | ADMIN | 上架/下架切换 |
| `/api/admin/notices/{id}` | DELETE | ADMIN | 删除 |
| `/api/notices` | GET | 登录 | 员工端：仅已发布，置顶优先 + 发布时间倒序 |
| `/api/notices/{id}` | GET | 登录 | 详情；员工访问已下架公告返回 403 |
