# 轻量 OA 系统 — 具体技术实现文档

> 版本：v2.0 ｜ 日期：2026-09-18 ｜ 配套：《系统设计文档.md》《功能详解文档.md》《接口说明文档.md》

## 1. 技术栈与约束（延续 v1，不引入重型依赖）

| 层 | 技术 | 说明 |
|---|---|---|
| 后端 | Spring Boot 3.3.5 / JDK23 | 三层结构 Controller → Service → Mapper |
| 持久 | 原生 MyBatis + XML + PageHelper | 禁 MyBatis-Plus（实习任务书） |
| 鉴权 | JJWT 0.12 + HandlerInterceptor | 角色校验 / Token 续期 |
| 密码 | spring-security-crypto (BCrypt) | 仅 crypto 模块 |
| 文件 | 本地磁盘 + Spring MultipartFile | 上传目录 `oa.upload-dir` |
| 报表 | Excel 兼容 CSV（UTF-8 BOM） | 不引入 POI |
| 日志 | @OpLog 注解 + AOP 切面 | spring-boot-starter-aop |
| 前端 | Vue3 + Element Plus + Vite + Axios | 新增页面沿用现有模式 |

> 新增依赖仅 `spring-boot-starter-aop`（Spring 官方模块，同族闭环）。

### 2.4 审批流程

```sql
CREATE TABLE flow_form (            -- 表单定义
  form_id BIGINT AUTO_INCREMENT PRIMARY KEY, form_name VARCHAR(60),
  form_key VARCHAR(40), remark VARCHAR(255), built_in TINYINT DEFAULT 0,
  status TINYINT DEFAULT 1, create_by BIGINT, create_time DATETIME DEFAULT CURRENT_TIMESTAMP
);
CREATE TABLE flow_form_field (      -- 表单字段
  field_id BIGINT AUTO_INCREMENT PRIMARY KEY, form_id BIGINT,
  field_key VARCHAR(40), label VARCHAR(50),
  field_type VARCHAR(20),          -- TEXT/NUMBER/DATE/SELECT/MULTI_SELECT/ATTACHMENT
  options VARCHAR(500),            -- JSON 候选值
  required TINYINT DEFAULT 0, sort_no INT, KEY idx_ff_form (form_id)
);
CREATE TABLE flow_def (             -- 流程定义
  def_id BIGINT AUTO_INCREMENT PRIMARY KEY, form_id BIGINT, def_name VARCHAR(60),
  category VARCHAR(30),            -- leave/overtime/travel/requisition/custom
  built_in TINYINT DEFAULT 0, status TINYINT DEFAULT 1, create_time DATETIME DEFAULT CURRENT_TIMESTAMP
);
CREATE TABLE flow_node (            -- 流程节点
  node_id BIGINT AUTO_INCREMENT PRIMARY KEY, def_id BIGINT, node_name VARCHAR(60),
  node_type VARCHAR(20),           -- APPROVAL/END
  sort_no INT,
  approver_type VARCHAR(20),       -- ROLE/DEPT_LEADER/SPECIFIC_USER/OWN_DEPT
  approver_ids VARCHAR(200),       -- ROLE→角色值；SPECIFIC_USER→user_id 逗号
  branch_field VARCHAR(40), branch_op VARCHAR(10), branch_value VARCHAR(100),
  branch_to_node_id BIGINT, next_node_id BIGINT,
  KEY idx_fn_def (def_id)
);
CREATE TABLE flow_instance (        -- 流程实例（审批单）
  instance_id BIGINT AUTO_INCREMENT PRIMARY KEY,
  def_id BIGINT, form_id BIGINT, def_name VARCHAR(60), category VARCHAR(30),
  title VARCHAR(120), applicant_user_id BIGINT, applicant_emp_id BIGINT, applicant_name VARCHAR(30),
  form_data_json TEXT,             -- {fieldKey: value} JSON
  status VARCHAR(20),              -- DRAFT/APPROVING/APPROVED/REJECTED/WITHDRAWN
  current_node_id BIGINT, create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
  finish_time DATETIME, deleted TINYINT DEFAULT 0,
  KEY idx_fi_app (applicant_user_id), KEY idx_fi_status (status)
);
CREATE TABLE flow_task (            -- 审批任务
  task_id BIGINT AUTO_INCREMENT PRIMARY KEY,
  instance_id BIGINT, node_id BIGINT, node_name VARCHAR(60),
  assignee_user_id BIGINT, assignee_name VARCHAR(30),
  status VARCHAR(20),              -- PENDING/APPROVED/REJECTED/WITHDRAWN/TRANSFERRED
  comment VARCHAR(500), handle_time DATETIME, KEY idx_ft_assignee (assignee_user_id, status)
);
CREATE TABLE flow_comment (         -- 审批链路时间线
  comment_id BIGINT AUTO_INCREMENT PRIMARY KEY,
  instance_id BIGINT, task_id BIGINT, user_id BIGINT, username VARCHAR(30),
  action VARCHAR(20),              -- SUBMIT/APPROVE/REJECT/TRANSFER/WITHDRAW/COMMENT
  content VARCHAR(500), create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
  KEY idx_fc_inst (instance_id)
);
```

## 3. 后端实现要点

### 3.1 角色与数据范围

- `UserPrincipal` 扩展 `deptId`（JWT 签发时从员工档案取，`ADMIN` 为 null 表示不限）。
- 拦截器新增规则：
  - `/api/admin/**` → 仅 `ADMIN`
  - `/api/dept-admin/**` → `ADMIN` 或 `DEPT_ADMIN`
  - 其余 `/api/**` → 登录即可
- 部门范围工具：`DeptScopeUtil.getScopeDeptIds(principal)` → 本部门 + 直属子部门（`ADMIN` 返回 null 表示不限）。所有部门管理员接口的 Mapper 查询带 `deptIds` 集合。

### 3.2 操作日志（@OpLog 切面）

```java
@Target(METHOD) @Retention(RUNTIME)
public @interface OpLog {
  String type() default "";      // LOGIN/FLOW/FILE/NOTICE/DEPT/EMP/CONFIG/...（默认空时取 op_type）
  String biz() default "";       // 业务名
  String op() default "";        // 动作，如 同意/驳回/发布
}
```
切面在方法成功后构建 detail（可读 SpEL 或固定文案），写入 `sys_op_log`；
校验 `UserContext`/请求 IP；`AUTH` 登录成功单独记录。

### 3.3 消息中心

- `MessageService.send(receiverUserId, type, title, content, bizLink)`：尊重 `message_push_enabled` 开关。
- 触发点统一在 Service 层：
  - 审批提交 → 通知第一审批人
  - 同意/驳回/撤回 → 通知发起人；同意 → 通知下一节点审批人
  - 公告发布 → 通知 **启用状态的全体员工**（广播）

### 3.4 审批流程引擎

提交（`FlowService.submit`）：
1. 读取 `flow_def` + 表单字段做必填校验；
2. 持久化 `flow_instance`（status=APPROVING，formData 转 JSON）；
3. `resolveNext(instance, def, startNodeId)`：解析首节点审批人（按 approver_type），创建首个 `flow_task`；
4. 写 `flow_comment(SUBMIT)` + 发消息。

同意（`FlowService.approve`）：
1. 校验任务 `PENDING` 且 assignee=当前人；
2. 任务置 APPROVED、写意见；
3. 判断分支：`branchField` 命中且 `branch_to_node_id` 存在 → 走后节点；否则 `next_node_id`；
4. 下一个节点存在 → `resolveNext` 开新任务 + 发消息；否则实例 APPROVED + finish_time + 联动考勤；
5. 写 `flow_comment(APPROVE)`。

驳回：任务 REJECTED、实例 REJECTED、通知发起人。
转办：原任务 TRANSFERRED（含转办记录），给目标新开 PENDING 任务，写 TRANSFER 意见。
撤回：仅实例 APPROVING 且当前人是发起人；实例 WITHDRAWN，关闭全部 PENDING 任务，通知各被指派审批人（消息弃置可选）。

分支条件比较：`form_data_json` 解析后按字段类型比较（数字型走数值比较；SELECT 走等于；MULTI_SELECT 走包含）。

### 3.5 考勤联动

- `AttendanceService.syncFromFlow(instance)`：
  - `category=leave`：解析请假起止日，逐日生成 `LEAVE`（跳过休息日）；
  - `category=overtime`：生成 `OVERTIME` 记录。
- 打卡流程：取生效 `att_rule`（enabled=1 最近一条）→ 定位校验（可选）→ upsert 当天 `att_record`，按时间判定 NORMAL/LATE/EARLY_LEAVE。

### 3.6 文档中心

- 树接口：一次性返回 `{folderId,...children[]}` + 各目录文件列表（分页做大目录懒加载）。
- 权限判定递归到根：无显式授权 → 继承父级；根目录兜底：read=所有人 / edit=ADMIN 或文件夹创建者。
- 上传两段式：`POST /api/doc/files/upload` 存盘并写 `doc_file`，返回 `fileId` 供预览/版本。
- 覆盖：同名文件存在且 `overwrite=true` → 当前内容移入版本表，写入新内容，`version_num+1`。
- 下载/预览走 `/api/doc/files/{fileId}/download`（JWT 鉴权 + 权限校验），`inline` 用于预览、`attachment` 用于下载。
- 附件路径统一 `UploadPath` 工具：`dir/yyyymm/filename-uuid.ext`。

### 3.7 报表导出

`GET /api/admin/attendance/report-month?month=2026-09`：
- 先按人按月计算指标（应出勤天数 = 工作日数 - 请假天数），返回 JSON；前端也可预览。
- `GET /api/admin/attendance/report-month/export?month=...`：写 UTF-8 BOM CSV，Content-Disposition attachment，Excel 直接打开列对齐。

## 7. 简化实现说明（技术取舍）

对应《功能详解文档.md》第 8 节 S1–S7，技术侧实现与理由如下：

| 编号 | 简化实现 | 技术理由 |
|---|---|---|
| S1 | 表单设计采用「点击添加 + 上下排序」，前端 `FormDesign.vue` 维护字段数组顺序，落库 `flow_form_field.sort_no` | 避免引入拖拽库（保持依赖最小），字段顺序即渲染与执行顺序，能力等价 |
| S2 | 岗位为 `emp_employee.position`（VARCHAR，默认 `''`） | 轻量；不建岗位字典表，避免岗位-人员双重维护 |
| S3 | 权限通过 `sys_user.role`（ADMIN/DEPT_ADMIN/EMPLOYEE）+ 拦截器前缀校验（`/api/admin/**`、`/api/dept-admin/**`）+ 前端菜单裁剪实现 | 轻量 RBAC；不引入权限点表，减少配置复杂度 |
| S4 | 报表导出为 UTF-8 BOM 的 CSV（`text/csv`），`AttendanceService.exportCsv` 拼装 | **不引入 Apache POI**（保持依赖最小、构建稳定）；Excel 双击可直接识别列 |
| S5 | 公告附件表 `sys_notice_attachment` 记录绑定；删除单附件走独立接口（`noticeService.deleteAttachment`），编辑弹窗仅展示上传 | 编辑弹窗内移除附件的交互复杂度（已发布公告的附件回收）留待后续 |
| S6 | 定位打卡用浏览器 `navigator.geolocation`，经纬度随 `PunchDTO` 提交，后端 Haversine 计算半径 | 无需原生端；Web 端即可完成定位校验 |
| S7 | 休息日以 `att_rule.rest_days`（JSON 数组，0–6 表示周日–周六）维护，代码映射到 `DayOfWeek` 判断 | 轻量；法定节假日/调休日历表留待后续 |
