## 1. 项目概述

### 1.1 背景与定位

本系统基于已搭建的数据中心网络环境（服务器 VLAN、VPN 远程访问、防火墙端口策略）开发，
用于验证数据中心网络的高可靠性与低延迟特性。系统采用**前后端分离架构**，覆盖企业日常办公的
员工管理、部门管理、公告管理等核心业务，分为**管理员端**与**员工端**两类角色。

## 3. 角色与权限体系

| 角色 | role 标识 | 权限范围 |
|---|---|---|
| 管理员 | `ADMIN` | 员工/部门/公告全量管理、仪表盘、个人中心 |
| 普通员工 | `EMPLOYEE` | 个人工作台、查看个人信息/修改资料与密码、浏览已发布公告 |

- 登录后签发 JWT（payload 含 `userId`、`username`、`role`、`empId`），有效期 2 小时；
  请求携带 `Authorization: Bearer <token>`，接近过期时响应头 `X-Renew-Token` 下发续期 Token，前端自动替换。
- 拦截器统一校验 Token；`/api/admin/**` 前缀接口额外校验 `role == ADMIN`，越权返回 `403` 业务码。
- 白名单：登录、注册、用户名唯一性校验。

## 5. 后端设计

### 5.1 包结构（com.tianyu.oasystem）

```
├── OaSystemApplication.java
├── common/        Result、ResultCode、PageResult、BusinessException、GlobalExceptionHandler
├── config/        CorsConfig、WebMvcConfig（拦截器注册）
├── interceptor/   JwtInterceptor、角色校验
├── util/          JwtUtil
├── entity/        SysUser、EmpEmployee、SysDept、SysNotice
├── dto/           LoginDTO、RegisterDTO、EmployeeDTO、EmployeeQueryDTO、DeptDTO、NoticeQueryDTO、ProfileDTO、PasswordDTO
├── vo/            LoginVO、EmployeeVO（join 部门名）、DeptVO（树）、NoticeVO、DashboardVO
├── mapper/        + resources/mapper/*.xml（手写 SQL，#{ } 防注入）
├── service/       接口 + impl（事务控制）
└── controller/    AuthController、EmployeeController、DeptController、NoticeController、UserController、DashboardController
```

### 5.2 统一返回与异常

`Result{code, message, data}`；`code`：200 成功 / 400 参数错误 / 401 未认证 / 403 无权限 / 404 不存在 / 500 服务器错误。
自定义 `BusinessException`，`GlobalExceptionHandler` 捕获业务异常、`MethodArgumentNotValidException`（字段级错误信息）、系统异常。

### 5.3 关键业务规则

- 注册：用户名唯一、密码强度（≥6 位含字母数字）、手机号 `1[3-9]\d{9}`、邮箱格式；默认 EMPLOYEE；注册时同步创建员工档案（工号自动生成 `EMP+年份+4位序号`）并关联。
- 员工删除：级联逻辑删除其登录账号（先删 user 再删 employee，Service 层事务）。
- 部门删除：存在在职员工或子部门时禁止删除。
- 禁用账号：`sys_user.status=0`，登录时拒绝并提示。
- 重置密码：管理员重置后统一为 `123456`。

## 7. 前端设计

### 7.1 视觉方案

| Token | 值 | 用途 |
|---|---|---|
| `--brand-navy` | `#0E2238` | 侧边栏、登录品牌面板底色 |
| `--brand-primary` | `#1A56A8` | 主按钮、链接、选中态（覆盖 Element primary） |
| `--brand-signal` | `#38BDF8` | 信号青：网络拓扑连线、焦点态、图表高亮 |
| `--surface` | `#F2F5F9` | 页面浅灰背景 |
| 正文/标题 | `#22303F` / `#0E2238` | PingFang SC / Microsoft YaHei |
| 数据字体 | Consolas/等宽 | 工号、统计数字（台账感） |

- **签名元素**：登录页左侧品牌面板为动态「数据中心网络拓扑」SVG——节点连线 + 数据包光点沿链路流动，
  呼应「验证数据中心网络」的项目背景；仪表盘统计卡复用小拓扑角标。除这两处外保持克制。
- 布局：登录页左右分栏卡片；后台 = 藏青可折叠侧栏 + 白色顶栏（面包屑 + 头像下拉）+ 浅灰内容区卡片。
- 员工端同一布局，仅菜单收敛（工作台/我的信息/公告中心），弱化视觉管理属性。

### 7.3 交互规范落地

表单提交前置校验并定位错误字段；表格 loading 遮罩；斑马纹 + 边框 + 分页固定右下；
删除/批量操作 `ElMessageBox` 二次确认；操作结果统一 `ElMessage`；未登录访问受限路由重定向 `/login`。

## 8. 跨域与联调方案

- 后端全局 CORS：`allowedOriginPatterns=*`、`allowCredentials=true`、暴露 `X-Renew-Token`、允许 `Authorization` 头。
- 前端 Axios `baseURL=http://localhost:8080/api`；生产建议 Nginx 反代统一域名。
- 联调顺序：接口自测（curl/Postman）→ 登录链路 → 各 CRUD → 权限隔离（员工访问 admin 接口应 403）。
